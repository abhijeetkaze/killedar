# Killedar · किल्लेदार

*The keeper of a Maratha fort — this one fits in your pocket and works where the network doesn't.*

An offline trek companion for Sahyadri forts near Pune. Plan at home in a minute, then put the
phone away. On the fort, with no signal, ask questions and hear the fort's story — answered by
**Gemma running on your phone**.

Built for the [DEV Hacktoberfest 2026 Open-Source AI Challenge, Week 1: Touch Grass](https://dev.to/challenges/hacktoberfest-week1-2026-10-05).
Repository started **2026-10-10**.

## What it does

| Screen | Works offline | What happens |
|---|---|---|
| **Plan** | Partly | Pick a fort and trail. Killedar predicts *your* climb time from your past hikes (TabPFN) and works backwards from the last bus so you know when to leave Pune. Offline, it uses Naismith's rule. |
| **Ask** | Yes | Questions answered on-device by Gemma via WebLLM, grounded only in that fort's notes. English or Marathi. |
| **Listen** | Yes | Fort history read aloud — ElevenLabs narration bundled with the app, or the phone's own voice. |

## Why open models

The top of a Sahyadri fort usually has no signal, so a hosted API is useless exactly where you need
it. Open weights run on the phone, cost nothing per question, and your hiking history never leaves
your own server.

## Architecture

```
web/  PWA, zero runtime deps          api/  Starlette, online-only
  domain   pure rules, prompt           domain    features, Naismith baseline
  ports    LanguageModel, Predictor     ports     ClimbTimeModel
  app      planTrek, askFort            adapters  TabPFN, CSV, Naismith
  adapters WebLLM (Gemma), HTTP, data   app       /predict, /health
  ui       Plan / Ask / Listen
  service worker → shell, forts, audio precached; WebLLM caches model weights
```

Ports-and-adapters on both sides, with dependencies pointing inward. See [CLAUDE.md](CLAUDE.md) for the rules.

## Run it

```bash
# web — Node 22.18+
cd web && npm install && npm run check && npm run serve      # http://localhost:5173

# api — Python 3.11+
cd api && python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m unittest discover -s tests -t .
uvicorn killedar_api.main:app --port 8000
# then build the web app against it:
cd ../web && KILLEDAR_API_URL=http://localhost:8000 npm run build
```

On a phone: open the deployed site in Chrome on Wi-Fi → Plan → **Download trail guide** →
switch to airplane mode → Ask.

### Your own hikes

Export past hikes (Strava, Google Fit, GPX) into `api/data/hikes.csv`:

```
distance_km,elevation_gain_m,start_hour,group_size,duration_min
3.0,600,7,2,118
```

`duration_min` is trailhead → summit. You need at least 8 rows; 20+ is better. Then compare models:

```bash
python -m killedar_api.evaluation data/hikes.csv
```

`data/hikes.sample.csv` is **synthetic** (generated by `data/make_sample.py`) so the API runs out of the box.
`data/hikes.csv` is currently **synthetic too** (`python data/make_sample.py --trails`: the fake hiker
climbing the app's real fort trails) — a placeholder until real hikes replace it.

### Narration

```bash
ELEVENLABS_API_KEY=… ELEVENLABS_VOICE_ID=… npm run audio
```

## Fort data

`web/public/forts/*.json` was written from the cited public sources (Wikipedia, linked in each file)
and is marked `"verified": false`. Bus and train times are deliberately left blank; the app asks you
for them. Please confirm details locally before relying on them, and send corrections.

## Deploy

`render.yaml` is a Render Blueprint: a static site for `web/` and a Python web service for `api/`.
TabPFN on CPU may need more than the free tier's 512 MB of memory.
